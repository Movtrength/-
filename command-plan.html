당신에게 맞는 형태 — 세 레인 한 창

코칭은 오늘을 돈다. 빌드는 한 런을 돈다. 볼트는 받지, 돌리지 않는다.
레인 1 코칭

today.html이 돈다. dashboard.html은 잠긴 칸의 판. 한 변수 = Prediction → 판정 → Actual. 이 카드에서 승인하지 않는다.

레인 2 빌드

커서 + 그록. 좌석 여섯: intake · plan · implement · verify · pr · handoff. 머신 점(RUNNING)은 좌석이 아니다.

레인 3 볼트

_INDEX.md 여섯 제목. 닫힌 날과 닫힌 빌드만 받는다. Dataview 시계를 홈에 두지 않는다.

퓨즈 Count

같은 레포 RUNNING이 셋이면 새 빌드를 열지 않는다. 이 분석 중 에이전트 6이 같은 레포에 떴다.

빌드 카드 넷 + 퓨즈

  1. Seat — 지금 좌석 · 머신 점 · 에이전트 링크 · 이번 런 변수 하나
  2. Ask — today.html과 같은 의식. 세 줄. 승인 또는 그 번호와 고친 한 줄. 물을 것이 없으면 숨긴다.
  3. Evidence — 프리뷰 · 스크린샷 · 무엇을 눌렀나. 아티팩트 없으면 Verify가 아니다.
  4. Handoff — 브랜치 · PR · CI · 다음 에이전트가 읽을 파일

머신 상태와 작업 좌석을 한 알약으로 합치지 않는다. RUNNING이 진척이 아니다. IDLE이 끝이 아니다.

볼트 홈 — _INDEX.md

손 링크. 쿼리가 필요하면 제목이 틀린 것입니다.

  1. Inbox — 아직 안 꽂은 닫기
  2. 이 블록 — 가설 + 마지막 증거 쌍. 디데이 없음
  3. Area — 이름 · 프로필 · Category · 마지막 변수
  4. 말 (Exit) — 혼자 칸
  5. 글 (한마디) — 혼자 칸. 말과 한 줄로 강제하지 않는다
  6. 자산 — 다시 쓴 것만. 비어 있으면 맞다

볼트 홈에 RUNNING · 스프린트 · 열린 열기 · 최근 수정을 올리면, 블록을 오늘 안에서 증명하는 것과 같은 버그입니다.

닫힌 것이 어디로 가나

닫힌 코칭 날

이름·프로필·Category → Area. Actual → 관찰. Exit → 말. 한마디 → 글. 증거 쌍 → 이 블록. 자산은 한 번 더 쓸 때만.

닫힌 빌드

프롬프트·디프 → Inbox. 2–6주 가설이면 이 블록. 다시 쓴 문장만 자산. RUNNING=false를 홈에 쓰지 않는다.

이미 있는 OS와 충돌하면

  • index.html을 앱 껍질로 다시 짜지 않는다. 주차 아웃풋 엔진. 고치지 않는다.
  • dashboard.html의 1 · 5 · 4 통계에 빌드 숫자를 넣지 않는다.
  • 볼트를 최종 온톨로지로 선언하지 않는다. 최종이 웹인지 노트인지는 확인 필요.
  • 세션 노트 더미를 자산이나 커리어로 부르지 않는다.
  • 닫기의 주인을 업로드·공유·퍼블리시로 되돌리지 않는다.
